# 设计说明

本文件记录项目的架构与关键设计决策。开发过程的实施计划已随代码完成而移除（可从 git 历史取回）。

## 定位

`image-classifier-gui`（Kimi / DeepSeek 双服务商版）的 **DeepSeek 单模型版**：
界面更简洁、固定使用 DeepSeek 视觉模型（`deepseek-flash`），保留评估实验室。

## 架构

| 模块 | 职责 |
|---|---|
| `main_window.py` | 主窗口：三个页面 + 状态栏主题切换 |
| `theme.py` | 浅色 / 夜间双主题（QSS + QSettings 持久化） |
| `config_tab.py` | 配置页：密钥、目录、分类、关键词、提示词、频率、预览测试 |
| `run_tab.py` | 运行页：进度、日志、统计、导出 |
| `eval_tab.py` | 评估页：数据集、多轮/AB/快速模式对比、混淆矩阵、阈值曲线、错误缩略图、历史对比 |
| `classifier.py` | 分类线程（线程池并发 + 判重 + 低置信度分流 + 快速模式） |
| `evaluator.py` | 单轮评估：抽样 + `RoundConfig` + `classify_samples` 并发核心 + 记录构建 |
| `eval_batch.py` | 多轮/多变体编排：`Variant` + 轮内交替排期 + `run_batch` + `BatchEvaluator` |
| `eval_stats.py` | 纯统计函数：多轮聚合 / 跨轮一致率 / 多数投票 / 阈值曲线 / 配对比较 |
| `vlm.py` | 视觉调用共享层：提示词构建 / 四级解析 / 时隙限速器 / 连接复用 / 参数自动降级 |
| `image_prep.py` | 图像预处理：EXIF 校正、>1024px 缩图、JPEG q85 |
| `eval_store.py` | 评估历史、固定评估集、批次分组的持久化 |
| `providers.py` | 服务商注册表（固定 DeepSeek，保留扩展点） |
| `secure.py` | Windows DPAPI 加解密（API Key 存储） |
| `tools/eval_cli.py` | 命令行评估：不开界面跑多轮 / A-B / 快速模式对比 |

数据流：`配置页 → Classifier / BatchEvaluator → vlm.classify_image → 解析 → 归档 / 统计`
（分类与评估共用同一套提示词构建与解析逻辑，避免行为分叉；评估的两条入口
——界面与命令行——共用 `eval_batch` + `eval_stats`，避免统计口径分叉）

## 关键决策

**图像管线**：EXIF 校正为纯增益（修复竖拍图方向）；模型内部按缩小图理解且图片 token 有上限（约 384/张），上传超 1024px 的原图只是浪费流量与费用，故默认"超过 1024px 才缩图"（LANCZOS + q85）。保留「原图模式」开关作为保险。

**并发与限速**：时隙限速器在并发下仍严格守住 RPM；连接复用省去每张图的 TLS 握手。瓶颈通常是单张响应时间（3-4 秒），提高并发数比提高 RPM 更有效。

**判重**：键为「文件名 + 大小 + 修改时间」；输出重名自动加序号（`a_1.jpg`），判重时对序号名做基名归一（仅剥离 1~2 位数字，避免误伤 `photo_2024.jpg`）。

**四级响应解析**：JSON → `分类||置信度||关键词` → 模糊匹配 → 未整理，保证提示词改动或模型输出格式变化时不会整批失败。

**低置信度分流**：低于阈值的图片归入 `待确认/`，不污染分类结果。实测默认 0.6 阈值几乎无效
（全量评估中只拦下 1.8% 的错误），但**也没有更高的阈值能救回大部分错误** —— 详见下方实测经验。

**配置存储**：应用配置在注册表 `HKCU\Software\DeepSeekImageClassifier\Config`（API Key 经 DPAPI 加密）；评估历史与固定评估集在 `%APPDATA%\DeepSeekImageClassifier\eval\`。

**评估为什么必须多轮**：API 采样本身带随机性（同一提示词、同一张图，推理长度可在 87~1244 token
之间波动），单轮结果不足以支撑结论。因此评估的默认设计是「多轮 + 配对比较」，
而不是「跑一次看总数」。

**参数降级而非硬失败**：`thinking` 等附加参数若被服务端拒绝（HTTP 400/404/422），
`vlm.classify_image` 会记住该模型不支持此参数、去掉它立即重试，并产生一条提示 ——
既不静默失败，也不让后续每张图都白试一次。

## 实测经验

**准确率**（276 张、11 类、固定评估集）：58%~66% 区间。类别体系是主要瓶颈 ——
"画风"（动漫）与"题材"（政治/历史/军事）混在同一层级时，模型倾向按画风归类；
让某一类成为兜底类（如"日常"）会持续吸走其他类的图片。

**提示词 A/B 实测**（276 张 × 2 轮 × 4 变体，轮内交替）：

| 变体 | 准确率 | 配对结果 |
|---|---|---|
| 现状（详细版：判定优先级 + 分类别分流规则 + 置信度分档） | **64.3%** | — |
| 简洁版（只留分类定义 + 3 条原则） | 58.5% | **−5.8pt，p=0.0019 → 显著** |
| 详细版 + 关思考 | 59.6% | −4.7pt（p=0.143） |
| 简洁版 + 关思考 | 55.4% | −3.1pt（p=0.345） |

**结论：详细版显著优于简洁版**（两个思考条件下都成立，合并 48:14，p=0.00002）。
早先"规则越多越负迁移"的假设在本数据集上**不成立** —— 前提是规则要针对真实混淆对
（画风误吸、兜底类误吸），而不是泛泛堆砌。

**评估噪声（已量化）**：

| 样本量 | 同提示词多轮极差 |
|---|---|
| 276 张全量 | 2.2pt（3 轮：61.6 / 59.4 / 61.2%） |
| 60 张子集 | 5.0–6.7pt（3 轮） |

且**符号会翻转**：60 张子集上「关闭思考」首轮显示 −3.3pt，重复 3 轮后变为 +1.7pt。
结论：样本越少越不能信单轮；跨提示词比较必须用 A/B 配对 + 二项检验。

**错误检测信号（276 张 × 3 轮，按图多数票）**：总错误 109 张，其中

| 判据 | 分流张数 | 分流精度 | 挡错率 | 误挡率 |
|---|---|---|---|---|
| 置信度均值 < 0.60（默认阈值） | 2 | 100% | **1.8%** | 0.0% |
| 置信度最低值 < 0.75 | 56 | 66.1% | 33.9% | 11.4% |
| 跨轮分歧 | 46 | 63.0% | 26.6% | 10.2% |
| 分歧 **且** 均值 < 0.80（求准） | 24 | **70.8%** | 15.6% | **4.2%** |
| 分歧 **或** 均值 < 0.80（求全） | 82 | 61.0% | **45.9%** | 19.2% |

**核心结论**：默认 0.6 阈值形同虚设；跨轮分歧是比自报置信度更可靠的信号；
但**即使最好的规则也只能拦下约 46% 的错误** —— 另一半错误是「既自信又稳定」的，
任何置信度/一致性信号都拦不住，只能靠更好的提示词或模型解决。

**多数投票**：3 轮投票相对单轮均值仅 +0.5pt（60.7% → 61.2%），
说明**多花 2 倍费用买投票不划算**；多轮的价值在"测量"而非"提升"。

## 类别体系改版（11 类 → 8 类）实测结果

用户拍板：**删除「动漫」**（精确率 12.5%、真实样本仅 3 张、却污染 14 张），
**「历史/政治/军事」合并为「史政」**，其余类别不动；**「日常」作为官方兜底类**（名称不变）。
实现方式为**评估期类别归并映射**（`app/category_map.py`），**不搬移任何素材文件夹**。

对比口径：同一批 273 张图、同一套标准答案（旧记录的标准答案与预测都按归并折算后比较）。

| 指标 | 原始 11 类 | 归并后（同口径） | **新 8 类实测**（3 轮） |
|---|---|---|---|
| 总准确率 | 63.4% | 69.2% | **68.5%**（各轮 68.1/68.9/68.5） |
| 具体类别精确率 | 67.5% | 74.6% | **74.9%** |
| 有害错误（进错文件夹） | 75 | 58 | **56** |
| 无害回流（→日常） | 26 | 26 | 29 |
| 轮间极差 | 2.2pt | — | **0.7pt** |

配对检验：旧 vs 新 **−0.4pt，12:11，p = 1.0000（完全不显著）**。

**核心结论：模型行为几乎没变。**

离线模拟（假设"模型行为不变、只是类别变粗"）预测 69.2%，实测 68.9%~69.2% —— **吻合**。
这说明：**+5.5pt 的收益 100% 来自类别体系变粗，而不是模型变聪明了**。
换 8 类并没有让模型"更好地理解图片"，只是让"政治 vs 军事"这类原本算错的判断不再算错。

**⚠️ 过度预测的问题没有消失，只是转移了。** 原先模型把 16 张图塞进「动漫」（精确率 12.5%）；
删除该类后，这些图流向别处，**「游戏」成了新的重灾区**：

| 新配置逐类 | 真实 n | 判定次数 | 精确率 | 召回 |
|---|---|---|---|---|
| 体育 | 22 | 17 | 88.2% | 68.2% |
| **史政** | 90 | 88 | **80.7%** | 78.9% |
| 经济 | 30 | 29 | 79.3% | 76.7% |
| 地理 | 28 | 24 | 75.0% | 64.3% |
| 学习 | 30 | 25 | 72.0% | 60.0% |
| 科技 | 30 | 26 | 65.4% | 56.7% |
| 日常（兜底） | 30 | 50 | 42.0% | 70.0% |
| **游戏** | 13 | 14 | **35.7%** | 38.5% |

垃圾桶排名：`→日常 29 张（34%）`、`→史政 17 张（20%）`、`→游戏 9 张（11%）`。

**跨轮一致性信号依然有效**：一致组准确率 73.8%（占 83.9%）vs 分歧组 43.2%（占 16.1%），
差 30.6pt —— 与 11 类时（65.2% vs 41.3%）同样可靠，可作为"该图需人工复核"的判据。

## 原始 11 类体系下的精确率视角（诊断依据，保留备查）

用户已决定**把「日常」作为官方兜底类**：无法明确归类时归入「日常」是可接受的结果
（名称保持不变）。在此口径下错误要分两类看：

- **无害回流**：真实类别 A 被判进「日常」→ 只是没进对文件夹，浏览「日常」即可捡回
- **有害错误**：真实类别 A 被判成另一个具体类别 B → 进了错误的文件夹，用户可能永远发现不了

实测（276 张，详细版提示词，按图多数票）：

| 指标 | 数值 |
|---|---|
| 旧口径（一切错判都算错） | 63.4% |
| 新口径（判进日常算待归类） | **72.8%** |
| 无害回流 / 有害错误 | 26 张 / **75 张**（40 种混淆模式） |
| **具体类别精确率**（模型说它是 X，真的是 X） | **67.5%**（231 次判定，156 次正确） |

逐类精确率 —— 模型"敢下结论"时约 **32% 是错的**：

| 类别 | 判定次数 | 正确 | 精确率 | 召回 |
|---|---|---|---|---|
| 体育 | 17 | 15 | 88.2% | 68.2% |
| 地理 | 18 | 15 | 83.3% | 53.6% |
| 经济 | 29 | 24 | 82.8% | 80.0% |
| 历史 | 21 | 16 | 76.2% | 53.3% |
| 学习 / 科技 | 25 | 19 | 76.0% | 63.3% |
| 军事 | 34 | 23 | 67.6% | 76.7% |
| 政治 | 36 | 19 | **52.8%** | 63.3% |
| 游戏 | 10 | 4 | 40.0% | 30.8% |
| **动漫** | 16 | 2 | **12.5%** | 66.7% |

**关键发现：`动漫` 是精确率灾难** —— 判定 16 次只有 2 次正确，而数据集中真实动漫只有 3 张。
召回 66.7% 说明模型"认得出"动漫，问题是**过度使用**它（把 14 张非动漫图塞了进去）；
提示词里"仅指没有现实题材指向的纯二次元作品"这条规则**未能约束住它**。
`政治` 同样：判定 36 次只对 19 次。**用户打开这两个文件夹时，多半看不到想要的东西。**

**置信度无法筛选（补证）**：错误样本的置信度均值**没有任何一张低于 0.6**；
阈值 0.6 → 0.7 只能多拦 13% 的错误，代价是误伤 2% 的正确。
→ **靠分流规则提升不了实际可用性，只能提高分类本身。**

**快速模式**（关闭模型思考）：单张 3.99s → 0.90s、输出 token 600 → 35（少 17 倍）；
276 张 × 2 轮配对下准确率 64.3% → 59.6%（−4.7pt，p=0.143）。

⚠️ **注意这个问题的结论曾两次翻转**：60 张子集 3 轮测试显示 **+1.7pt**（关思考更好，
配对 14:17），276 张测试显示 **−4.7pt**。两个思考条件下点估计都为负，
合并 41:25（p=0.064）—— **方向一致为负但未达显著**。

结论：**默认关闭**，需要吞吐时再由用户开启；不要把它当作"免费提速"。

**性能**（同批 276 张评估）：

| 配置 | 耗时 | 吞吐 |
|---|---|---|
| 原图直传 + 串行 + 30 张/分 | 25.6 分钟 | 10.8 张/分 |
| 图像管线 + 3 并发 + 120 张/分 | 6.1 分钟 | 45.1 张/分 |
| 图像管线 + 6 并发 + 240 张/分 | 2.9 分钟 | 93 张/分 |

**模型名**：`deepseek-v4-flash-vision-exp` 已退役（官方文档：请求仍被接受，但由
V4.1-Flash 代答并按 Flash 计费），默认值已改为 `deepseek-flash`。

## 后续方向（按优先级，尚未开工）

目标：**① 提高具体类别精确率（当前 74.9%）② 减少有害错误（当前 56 张）**。

| 优先级 | 行动 | 理由 |
|---|---|---|
| **P1** | 提示词翻转成**兜底模式**：「无法明确归入其他具体类别时一律归「日常」；**宁可给日常，也不要猜一个具体类别**」 | 把有害错误转化为无害回流；且模型现在在硬猜「游戏」等类，放开兜底可能直接减少乱猜 |
| **P2** | **处理「游戏」**：精确率 35.7%（判定 14 次对 5 次），已成为删动漫后的新重灾区 | 但评估集里只有 13 张 → **先补样本再谈改动**，否则改完测不出来 |
| **P3** | 收窄「科技」（精确率 65.4%）与「学习」（72.0%）的边界 | 两者互相与「日常」争夺 |
| **P4** | 评估报告增加**精确率视角**：具体类精确率 + 有害错误/无害回流拆分 | 让后续每次调优都能看见真目标，而不是被总准确率掩盖 |
| **P5** | 全量评估一次（905 张，约 ¥2 / 25 分钟） | 现有固定评估集是 09-10 的老快照（276/905），且各类样本极度不均 |

> **重要提醒**：已证明"让类别变粗"能提升数字，但**模型行为本身没变**。
> 下一步若要真正提升，必须针对**具体混淆对**改提示词（一次一条），而不是继续合并类别 ——
> 继续合并只会让文件夹越来越没用（准确率好看但信息量下降）。

其他：

- **评估集类别不平衡**：游戏仅 13 张、体育 22 张。游戏已成为最差类，**不补样本无法验证任何改动**
- 若快速模式的等价性要在更大样本上确认（当前 p=0.064 卡在临界），
  需要每类 ≥30 张 × 4 轮以上，成本约 ¥6
