# DeepSeek图片分类工具

用 **DeepSeek 视觉模型**（`deepseek-flash`）批量识别并归类本地图片的 Windows 桌面工具。

选好源文件夹 → 逐张送入视觉模型判断类别 → 按类别复制到输出文件夹，并给出置信度、关键词与统计报告；内置**评估实验室**，可用你自己的标注数据集测试、对比、迭代提示词。界面采用**浅色 / 夜间双主题**与可拖拽的左右分栏布局。

> 本仓库是 [`image-classifier-gui`](https://github.com/zyc771/image-classifier-gui)（Kimi / DeepSeek 双服务商版）的 **DeepSeek 单模型版**：界面更简洁，固定使用 DeepSeek 视觉模型。

## 功能特性

### 界面
- **浅色 / 夜间双主题**：状态栏右下角一键切换（🌙 夜间模式 / ☀ 日间模式），选择自动记住
- **左右分栏布局**：三个页面均为可拖拽分栏，拖动中间分隔条即可调整比例
  - 配置页：密钥 / 文件夹 / 分类列表 ↔ 每类关键词 / 提示词 / 图像处理 / 请求频率
  - 运行页：进度 / 控制 / 实时日志 ↔ 统计表 / 导出操作
  - 评估页：数据集 / 提示词 / 控制 ↔ 结果 / 历史对比
- **应用图标**：AI + 分类 + 图片三要素设计，多尺寸 ico（窗口与 exe 均生效）

### 分类
- **递归扫描**：源文件夹下任意层级的子文件夹都会被读取（剪映工程文件 `.vesf` 等非图片自动忽略）
- **图像预处理管线**：EXIF 方向校正 → 超过 1024px 才缩小（LANCZOS）→ JPEG q85 → base64 上传
  （模型内部本就按缩小图理解且单图 token 有上限，原图直传只是白费流量与费用；可在配置页勾选「原图模式」关闭该管线）
- **并发请求**：默认 3 并发 + 时隙限速器，并发下仍严格守住设定的请求频率
- **连接复用**：线程本地 HTTP Session，省去每张图的 TLS 握手
- **断点续跑**：按「文件名 + 大小 + 修改时间」判重，已处理的图片自动跳过
- **重名保护**：不同子文件夹的同名图片输出时自动加序号（`a.jpg` → `a_1.jpg`），不会互相覆盖
- **低置信度分流**：置信度低于阈值（默认 0.6）的图片进入 `待确认/` 文件夹，不污染分类结果
  （评估实验室可扫描阈值曲线，给出在当前数据集上更合适的阈值建议）
- **快速模式**（可选，默认关）：关闭模型思考，实测单张延迟 3.99s → 0.90s、输出 token 少 17 倍。
  服务端若不支持该参数会**自动降级并在日志提示**，不会静默失败或中断任务
- **失败重试**：单张最多 3 次重试；失败清单可导出 CSV
- **随时暂停 / 取消**：不阻塞界面

### 配置
- API 密钥使用 **Windows DPAPI 加密**存储（仅当前 Windows 用户可解密），非明文
- 分类列表、每类关键词、提示词模板、请求频率、并发数、图像处理模式全部可配置并持久化
- 提示词模板支持两个占位符：
  - `{categories}` → 分类列表（如 `科技、日常、学习`）
  - `{category_definitions}` → 分类定义块（由分类列表 + 每类关键词自动生成）
- 「单张预览测试」可在正式跑批前验证提示词效果

### 评估实验室
- 选定**已按类别分好文件夹**的数据集 → 批量测试当前提示词的真实准确率
- **固定评估集**：首次抽样后存档复用，保证多次评估结果可比（覆盖前自动备份 `.bak.json`）
- **重复轮次（1–5 轮）**：同一提示词多跑几轮取平均。**这是用评估实验室的前提** ——
  实测单轮准确率波动可达 5–7pt，不做重复几乎无法分辨真实差异
- **跨轮一致性**：统计每张图在多轮中的结果是否稳定，并给出「一致组 vs 分歧组」的准确率对比。
  实测分歧组准确率显著低于一致组，可作为「该图需要人工复核」的信号
- **多数投票**：自动计算「3 轮投票后」的准确率，回答"多花 2 倍钱能不能换来准确率"
- **阈值扫描**：记录**全部样本**的置信度，输出「挡错率 / 误挡率 / 分流精度 / 保留准确率」曲线，
  并给出在误挡预算内的建议阈值 —— 用于回答"低置信度阈值设多少才真的有用"
- **A/B 提示词对比**：两个提示词**轮内交替执行**（A、B、A、B…）以抵消 API 侧时间漂移，
  事后按**同一张图**做配对比较 + 二项检验，明确回答"差异是真的还是噪声"
- **快速模式对比**：同一提示词下对比「思考开 / 思考关」，可与其他对比项叠加
- **混淆矩阵**：一眼看出哪类被判成了哪类
- **错误缩略图列表**：双击直接打开原图，快速定位模型错在哪
- **历史对比**：每次评估自动存档，可选中两条对比，自动做配对分析并列出混淆对改善/恶化
- 导出错误清单 CSV / 单条结果 JSON / 整批记录 JSON

### 命令行评估（不开界面）
适合跑长实验或写进脚本 —— 与界面共用同一套编排与统计逻辑：

```powershell
# 3 轮同提示词：测噪声基线 + 一致率 + 阈值曲线
python tools/eval_cli.py --rounds 3

# 提示词 A/B，并交叉对比快速模式（4 个变体 × 2 轮，轮内交替）
python tools/eval_cli.py --rounds 2 --variant 现状=@config --variant 简洁版=prompt.txt --also-fast

# 临时抽样试跑（不写入固定评估集）
python tools/eval_cli.py --no-fixed --per-cat 10 --rounds 1 --no-save
```

## 快速开始

### 1. 获取 API Key
到 [DeepSeek 开放平台](https://platform.deepseek.com/) 创建 API Key（`sk-` 开头）。

### 2. 运行

```powershell
pip install -r requirements.txt
python main.py
```

打包成单文件 exe（产物在 `dist/`）：

```powershell
python build.py
```

### 3. 使用

1. **配置页**：填入 API Key → 选择源文件夹与输出目录 → 按需调整分类、关键词、提示词 → 点「单张预览测试」验证
2. **运行页**：点「▶ 开始分类」，实时查看进度、速度、预计剩余与日志；完成后查看统计表与 Token 消耗
3. **评估页**（可选）：选数据集 → 开始评估 → 看准确率与混淆矩阵 → 改提示词 → 再评估 → 对比历史

界面偏好：状态栏右下角的「🌙 夜间模式 / ☀ 日间模式」可随时切换主题（会记住）；三个页面的左右分栏都能用鼠标拖动分隔条调整宽度。

输出结构：

```
输出目录/
├── 科技/       ← 置信度达标的图片按类别归档
├── 日常/
├── ...
└── 待确认/     ← 低置信度图片（建议人工复核后手动归位）
```

## 提示词与分类定制

默认提示词要求模型**只输出 JSON**：

```json
{"category": "分类名", "confidence": 0.93, "keywords": ["关键词1", "关键词2"]}
```

解析器采用四级降级策略，兼容性很强：

```
JSON → `分类名||置信度||关键词` 旧格式 → 模糊匹配 → 未整理
```

**分类建议**：类别之间语义重叠越少，准确率越高。经验数据（约 280 张、11 类）：

- 题材与画风混在同一层级时，模型容易按"画风"归错（如二次元画风的时政梗图被判为动漫）→ 在提示词中明确**判定优先级：题材 > 画风**
- 避免让某一类成为"兜底类"（如"日常"吸收一切生活化场景）→ 明确各类的分流规则
- ⚠️ **评估存在随机性**：同一提示词、同一批图片，单轮准确率波动可达 **5–7 个百分点**
  （276 张全量评估实测极差 2.2pt，60 张子集实测极差 5.0–6.7pt；样本越少波动越大）。
  **比较两版提示词时请用「重复轮次 ≥3」+ A/B 配对比较**，只看单轮总准确率会得出错误结论 ——
  实测中就出现过"关掉思考准确率 −3.3pt"在重复 3 轮后翻转为"+1.7pt"的情况。
- ⚠️ **置信度阈值救不了大部分错误**：实测约 2/3 的错误样本置信度 ≥0.8（"自信地错"），
  当前默认 0.6 阈值在全量评估中只拦下 **1.8%** 的错误。提高阈值能多拦一些，
  但**错误样本中约有一半既自信又稳定**，靠任何置信度/一致性信号都拦不住 ——
  这类错误只能靠更好的提示词或模型来解决，不能指望分流规则。

## 性能参考

实测（276 张、11 类，评估模式）：

| 配置 | 耗时 | 吞吐 |
|---|---|---|
| 原图直传 + 串行 + 30 张/分 | 25.6 分钟 | 10.8 张/分 |
| 图像预处理 + 3 并发 + 120 张/分 | **6.1 分钟** | **45.1 张/分** |

调优建议：
- 请求频率可设到 600 张/分（前提是你的账号配额支持）
- 并发数默认 3；若日志中「失败」明显增多（HTTP 429 限流），降低并发或频率
- 当前瓶颈通常是单张响应时间（约 3-4 秒），提高并发数是最直接的提速手段

## 常见问题

**Q：日志里出现大量「失败」怎么办？**
多为 HTTP 429（触发限流）。降低「请求频率」或「并发数」，程序自带 3 次退避重试。

**Q：分类不准怎么办？**
用「评估」页跑一次基准 → 看混淆矩阵定位混淆对 → 针对性改提示词/分类定义或关键词 → 再评估对比（记得重复 2-3 次排除随机性）。

**Q：跑完发现某类图片不想要，能重跑吗？**
可以。已处理的图片会按「文件名+大小+修改时间」跳过；把输出目录里对应的图片删掉即可重新分类。图片自身的元数据（大小/修改时间）不会被修改。

**Q：数据会上传到哪？**
仅发送到你配置的 API 端点（`https://api.deepseek.com/chat/completions`）。图片不会上传到其他地方，输出文件只在本机复制。
